# Onboarding 與 BYOK 設定流

> **狀態**：規劃（尚未實作）
> **日期**：2026-10-07
> **目的**：定義使用者**第一次打開 App**時的流程，以及之後如何回到設定修改。
> **相關**：`INFORMATION-ARCHITECTURE.md`（整體 IA）、`ARCHITECTURE.md` §9（BYOK 架構）

---

## 0. 設計原則

| 原則 | 說明 |
|---|---|
| **不擋路** | Onboarding 最多 3 步，且**可全部略過**。使用者要能立刻開始用 |
| **AI 是選用** | BYOK 不在關鍵路徑上。沒有金鑰 → 單字填空照常可用 |
| **先講為什麼** | 依 `docs/DESIGN.md`：說明需求再要求，不要直接跳系統對話框 |
| **可回頭** | 每個 Onboarding 步驟都能在設定裡重做 |

## 2. 第 1 步：歡迎

**目的**：3 秒內讓使用者知道這個 App 做什麼。

```
┌─────────────────────────────────────┐
│                                     │
│           [App 圖示]                 │
│                                     │
│        用英文歌學單字                 │
│                                     │
│   搜尋你喜歡的歌，把歌詞挖空，         │
│   邊聽邊把單字記下來。                │
│                                     │
│                                     │
│         ● ○ ○                       │
│                                     │
│  ┌───────────────────────────────┐  │
│  │           繼續                 │  │  ← Filled Button
│  └───────────────────────────────┘  │
│              略過                    │  ← Text Button
└─────────────────────────────────────┘
```

| 元素 | 規格 |
|---|---|
| 圖示 | 由 `ic_launcher_foreground` 重用，96dp |
| 標題 | `headlineMedium`，置中 |
| 說明 | `bodyLarge`，`onSurfaceVariant`，置中，最多兩行 |

## 3. 第 2 步：隱私

**目的**：呼應 PRD 的「無帳號，資料只在本地」。這是信任基礎，不是法律樣板。

```
┌─────────────────────────────────────┐
│                                     │
│           [盾牌圖示]                 │
│                                     │
│      無帳號，資料只在本地             │
│                                     │
│  ┌───────────────────────────────┐  │
│  │ ✓ 字庫與學習紀錄只存在這台裝置  │  │
│  │ ✓ 不需要註冊、不收集個資        │  │
│  │ ✓ 不開啟雲端備份               │  │
│  └───────────────────────────────┘  │
│                                     │
│  唯一會連外的情況：                   │
│  • 搜尋歌詞（LRCLIB）                │
│  • 取得封面（iTunes）                │
│  • 使用 AI 功能時（你自己的金鑰）     │
│                                     │
│         ○ ● ○                       │
│                                     │
│  ┌───────────────────────────────┐  │
│  │           繼續                 │  │
│  └───────────────────────────────┘  │
│              略過                    │
└─────────────────────────────────────┘
```

> **這一步不是形式**。它明確列出「唯一會連外的三種情況」——
> 這比寫「我們重視您的隱私」有意义得多，而且與 `allowBackup=false`
> 和 `dataExtractionRules` 的實際行為一致。

### 5.2 Provider 預設值

選 provider 時自動填入端點與建議模型（**可編輯**）：

| Provider | Base URL | 建議模型 |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Anthropic | `https://api.anthropic.com/v1` | `claude-3-5-haiku-latest` |
| Gemini（相容層）| `https://generativelanguage.googleapis.com/v1beta/openai` | `gemini-2.0-flash` |
| **NVIDIA NIM** | `https://integrate.api.nvidia.com/v1` | `meta/llama-3.1-8b-instruct` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Groq | `https://api.groq.com/openai/v1` | `llama-3.1-8b-instant` |
| OpenRouter | `https://openrouter.ai/api/v1` | （使用者自填）|
| 自訂 | （空白，由使用者填）| （空白）|

> 全部走 **OpenAI 相容**格式（`/chat/completions`）。這是 Operit 的既有架構，
> 也是為什麼它能接這麼多 provider（見 `ARCHITECTURE.md` §9.2）。

### 5.3 金鑰儲存

| 項目 | 做法 |
|---|---|
| 存放位置 | **Android Keystore**（用 `androidx.security:security-crypto`）|
| DB 只存 | `keyAlias`（別名），**絕不存金鑰本體** |
| UI 顯示 | 預設遮蔽，可切換顯示 |
| 匯出 | **不匯出**。CSV 匯出只含字庫，不含金鑰 |

### 5.4 連接測試

```
1. 讀取金鑰（從 Keystore）
2. POST {baseUrl}/chat/completions
      { model, messages: [{role:"user", content:"ping"}], max_tokens: 5 }
3. 判定：
   200              → ✓ 連線成功（顯示延遲）
   401 / 403        → ✗ 金鑰無效
   404              → ✗ 端點或模型不存在
   429              → ⚠ 已達速率限制（金鑰有效，但請稍後或加金鑰）
   5xx              → ✗ 服務暫時無法使用
   逾時（15 秒）     → ✗ 無法連線（檢查網路或端點）
```

> **429 的處理是關鍵**：它代表「金鑰有效但被限流」，
> 這正是 KeyPool（多把金鑰輪替）要解決的問題。UI 應提示「可新增更多金鑰」。

## 6. 設定頁結構（PRD v2 的六類）

```
設定
├─ 1. 外觀與語言
│     ├─ 主題：跟隨系統 / 淺色 / 深色
│     └─ 語言：（繁中 / English）
│
├─ 2. 播放與音源
│     ├─ 音源選擇（⚠️ 尚未實作）
│     ├─ 單句循環       [開關]
│     └─ 播放速度       [滑桿]
│
├─ 3. 學習與複習
│     ├─ 每日目標（題數）
│     └─ 難度：A2 / B1 / B2
│
├─ 4. AI 與內容
│     ├─ AI 設定（BYOK）      →  §5 的表單
│     ├─ 辭典 API
│     └─ 單字分類 API
│
├─ 5. 資料與儲存
│     ├─ 字庫統計（唯讀）
│     ├─ 快取清除

│
└─ 6. 關於
      ├─ 版本
      ├─ GitHub

```

> **刻意不做**（依 PRD）：字號選擇、FSRS retention 開放調整、Nibomo MCP。

## 7. 資料模型

需要新增兩個 DataStore 項目（**不是 Room**——它們是設定，不是使用者資料）：

```kotlin
object OnboardingPreferences {
    val COMPLETED = booleanPreferencesKey("onboarding_completed")
    val SEEN_PRIVACY = booleanPreferencesKey("onboarding_seen_privacy")
}

object UserPreferences {
    val THEME_MODE = stringPreferencesKey("theme_mode")        // system / light / dark
    val LANGUAGE = stringPreferencesKey("language")            // zh-TW / en
    val SINGLE_LINE_LOOP = booleanPreferencesKey("single_line_loop")
    val PLAYBACK_SPEED = floatPreferencesKey("playback_speed")
    val DAILY_GOAL = intPreferencesKey("daily_goal")
    val DIFFICULTY = stringPreferencesKey("difficulty")        // A2 / B1 / B2
    val DICTIONARY_API = stringPreferencesKey("dictionary_api")
    val WORD_CATEGORY_API = stringPreferencesKey("word_category_api")
}
```

**為什麼設定放 DataStore 而非 Room**：設定的讀取頻繁、量小、不需要關聯查詢，
用 DataStore 更輕。Room 留給有結構的學習資料。
